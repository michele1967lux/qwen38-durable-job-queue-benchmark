## What this is

A durable local job queue on SQLite, built from scratch by
**Qwen3.8-27B** running as a coding agent through `ds-harness` on a
[Lucebox](https://github.com/Luce-Org/lucebox) backend, on an AMD Radeon AI
PRO R9700.

It was produced in a single session as a benchmark of greenfield design
capability, then evaluated independently.

## What it is not

**It is not software to use.** It is experimental evidence. It contains a
known substantive defect, left in place deliberately (see below).

## Result

**PASS with two defects.**

The system holds on the points the task set out to stress. It survived 17
adversarial tests written against the specification, without reusing any of
its own fixtures: lease ownership guarded by a token checked inside the same
atomic UPDATE, full ABA rejection, exactly one winner across 16 concurrent
claiming threads, exactly one job across 16 concurrent idempotent enqueues,
correct backoff and terminality, correct restart recovery, and a lease
boundary handled consistently between `claim()` and `recover()`.

The substantive defect is not in the code but in the documentation:
`DECISIONS.md` asserts three times that incrementing `attempts` at claim time
bounds total executions and drives a crash-looping job to `dead`. It does
not: `make_dead` is computed only inside `fail()`, and the expired-lease
reclaim path never compares `attempts` against `max_attempts`. A worker that
always dies leaves the job claimable indefinitely.

## Why the defect has not been fixed

Fixing it would destroy the experimental result. The delivered state is the
data.

The minimal fix is known — add `AND attempts < max_attempts` to the reclaim
branch, or transition to `dead` on expiry when attempts are exhausted — and if
it is ever applied it will go on a separate `post-judge-fixes` branch, leaving
`bench/qwen38-durable-job-queue` and the tag untouched.

## History integrity

The Git history is itself part of the evidence. The judge verified that the
governance files were committed before the implementation, that tests came
before the core, that every commit hash cited in the documents exists, and
that the single commit modifying tests **strengthened** its assertions rather
than weakening them.

The judged branch and tag are not to be rewritten.
